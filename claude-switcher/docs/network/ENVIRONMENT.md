# macOS 环境配置

macOS App 的「环境配置」集中提供网络、系统和 AdsPower 三类设置。入口位于主窗口、检查设置页与菜单栏。本页描述的是 macOS 新功能；Windows、Linux 和其他指纹浏览器没有对应的配置界面或相同联调范围。

首次使用或随包组件版本变化时，先点击「安装本机组件」，在终端完成完整安装和管理员验证，再返回「完成安装后重新检查」。完整安装会同步用户脚本与系统保护服务；仅替换界面不能完成组件升级。配置过程不会代替账号切换前的环境审计。

## 三类配置的范围

| 页面 | 可以配置 | 生效范围 |
| --- | --- | --- |
| 网络 | Clash Verge 托管分流、可选 DNS、缺组时自动创建、浏览器专用本机代理端口 | 代理客户端；应用或恢复会短暂重启 Clash Verge |
| 系统 | 按实际出口更新国家、时区、地区格式；应用既有地区目标并修复环境 | 本机系统设置、客户端语言、TUN、托管规则与保护服务；按操作要求进行管理员验证 |
| 指纹浏览器 | 读取 AdsPower 环境列表，为一个已关闭环境配置本机代理，以及能够读取并恢复的 WebRTC 设置 | 用户明确选择的 AdsPower 环境；不启动、关闭或批量修改浏览器环境 |

网络页设置是 Clash Verge 的配置入口，不能推定其他代理客户端也支持同一操作。系统页使用既有的 `set-region` 与 `fix` 流程，操作结束后重新检查环境。设备字体、GPU、浏览器版本等特征保持设备自身状态。

## 网络：固定安装时的代理组

「已安装代理组」只读显示本机安装时的组名。该组名同时用于用户脚本与 root 保护服务，不能只在界面中重命名。需要换组名时，应使用完整安装器同步相关组件。

开启「订阅缺少同名代理组时自动创建」后，托管配置会在订阅缺少该组时补建同名组。它沿用安装时的组名，不要求各订阅原本就带有这个组。

新创建的组首次默认选择 **REJECT**。这时流量会被阻断，界面会提示仍需完成的步骤，不能把“组已创建”当作网络可用：

1. 在 Clash Verge 中打开这个同名代理组，手动选择可用代理节点。
2. 回到网络页，重新「预览修改」并「应用配置」。
3. 查看验证结果，再回主界面重新检查环境。

应用前请先退出 Claude 桌面版和 Claude Code；检测到受保护客户端仍在运行时，后端会拒绝重启代理。

网络页先读取当前配置，再预览修改；改变端口或开关后需要重新预览。浏览器专用入口默认使用 `127.0.0.1:7898`，端口可在 `1024–65535` 内调整，仅供本机连接，并固定使用已安装的专用组。国内与局域网直连、Claude 与 IP 检测优先使用专用代理组，其余流量走代理；实际生效仍以运行配置及检查结果为准。

「应用托管 DNS 设置」控制配置写入。DNS 配置写入成功、fake-IP 回答或一次解析成功，都不能独立证明没有 DNS 泄漏。

## 系统：跟随实际出口

「按当前出口配置地区」重新识别出口国家，并同步时区、地区格式及保护服务的目标。更换国家节点后使用这一操作；不能把某个固定国家当作所有用户的默认目标。

「应用当前目标并修复环境」应用已保存的目标，并执行既有环境修复，包括客户端语言、IPv6、TUN、规则与保护服务等适用项目。它可能重启代理，并要求管理员验证。操作后仍有失败项时，界面显示尚未完成，而不是直接允许启动。

网络恢复按钮不撤销系统地区修改。需要换回原地区时，先恢复对应的实际出口，再重新配置地区；安装期间保存的可恢复系统原值由完整安装器和卸载流程管理，见 [安装更新说明](../INSTALL-UPDATE-TRANSACTIONS.md)。

## AdsPower：单个关闭环境的可恢复配置

先在 AdsPower 开启 Local API，并填写本机 HTTP 地址，默认是 `http://127.0.0.1:50325`。只接受回环地址，不向远程服务转发密钥。API Key 仅用于当前窗口，通过进程标准输入传递，不写入命令参数、环境变量或应用设置；关闭配置页时清空。

读取环境列表后选择一个环境，也可以手动填写环境 ID。配置前必须关闭这个环境；无法确认关闭状态时会拒绝写入。配置动作只管理代理和可安全恢复的 WebRTC 字段，不修改账号、Cookie、User-Agent、Canvas 或其他指纹字段。

- 本机代理：HTTP、主机 `127.0.0.1`、网络页设置的端口，用户名与密码留空。先在网络页启用并应用专用入口。
- WebRTC：只有 API 能读出原设置时，才能自动设置并保留恢复依据。API 未返回原设置时，只配置代理，显示手动任务；请在 AdsPower 中将该环境的 WebRTC 设为 Disabled，并在浏览器内验证。
- API 权限、套餐或版本不支持时，可使用页面中的「手动配置参数」。手动设置不属于工具可自动恢复的变更。

`ok: true` 表示请求执行成功，不必然表示全部配置完成。出现 `complete: false`、`partial` 或 `manual_required` 时，界面显示警告；完成剩余步骤后再验证。接口细节见 [AdsPower 配置说明](ADSPOWER.md)。

## 恢复与失败处理

网络页的「恢复上一次网络配置」使用本功能保留的单层备份，恢复最近一次实际写入前的网络配置。下一次实际写入会更新这份备份，不能连续撤销多次历史操作。恢复时也可能重启 Clash Verge。它不恢复系统设置或 AdsPower 环境；没有备份或无法确认恢复结果时，应按返回提示处理，不能据此认定已恢复。

AdsPower 页的「恢复选中环境」只恢复这个环境中由工具管理的代理和 WebRTC 字段。恢复记录按本机 API 地址与环境 ID 区分，保存在 `~/.claude-switcher/browser-proxy/` 的当前用户私有目录中。记录保留恢复所需的旧代理参数；原代理含用户名或密码时，这些参数也属于私有恢复资料，请勿公开。记录不包含 API Key、账号或 Cookie。

写入后会读回核对；失败时尝试恢复。若恢复无法确认，记录会保留并提示继续恢复。若用户或其他工具已把受管字段改为不同值，恢复不会覆盖该外部修改。已有恢复记录时，要先恢复，再配置新的目标端口或其他值。

配置运行期间，App 会阻止冲突操作及退出。配置成功和恢复成功都只描述该操作的结果，不能替代主界面的完整环境检查。

## 验证范围

原生界面已经过 Swift 编译和三页实际渲染检查。界面模型使用假核心脚本验证了预览失效、忙碌状态、JSON 标准输入、失败结果解析、部分完成提示和密钥脱敏；这些测试没有操作真实系统配置。另已在本机对四份订阅离线生成配置并通过 `Mihomo -t` 检查，其中三份覆盖缺组自动补建；该验证未切换真实订阅，也未验证切换后的实际出口。

AdsPower 自动化测试使用独立的本机假 API，覆盖所选环境必须关闭、读回核对、失败恢复、外部变更冲突、缺少 WebRTC 原设置、API 拒绝与重定向处理。它验证协议和恢复逻辑，不能证明某个实际 AdsPower 版本或套餐已联调通过。

下列结果需要在用户实际环境中验证，不能由隔离测试代替：

- Clash Verge 重启后实际使用预期规则、DNS 和本机监听端口；更换订阅后同名组正确补建，节点选择完成且运行验证通过。
- 管理员验证和实际系统设置变更正确完成；重新检查显示当前地区、路由与保护服务的真实状态。
- 实际 AdsPower Local API 的权限和字段能力、已关闭环境的写入读回与恢复，以及浏览器内 WebRTC 行为。
- Claude 的真实启动、登录和账号切换；本配置功能的隔离测试没有执行这些操作。

本功能没有新增整机抓包、浏览器 ICE 全面审计或网络层零泄漏证明。进程保护、DNS/STUN 检查和默认关闭的 PF 防护边界见 [网络检查与可选 PF 防护](README.md)。
