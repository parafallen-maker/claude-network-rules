# macOS 网络变化监控

`1.8.0-rc1.local3` 为 Clash Verge / Mihomo 增加持续监控和原生系统通知。国内直连的 51 条自有规则保持不变。

## 行为

- root 守护每秒启动一次本地检查，单次总超时 3 秒：验证 TUN 路由、实际规则表、代理内核及当前选中节点链。
- 独立线程每 5 秒通过明确指定的本地 HTTP 代理探测 Cloudflare 出口；请求不会回退直连。单次网络超时不立即停机，距最后成功结果超过 20 秒则停止 Claude 并提醒。
- VPN/代理证据失效、节点链变化、同一节点出口 IP 变化、出口国家不符都会停止 `/Applications/Claude.app` 的实际桌面进程。先冻结，再终止，并检查是否仍有残留；停止失败会继续重试且禁止恢复就绪。
- 监控刚启动、重新连接或节点切换后，需要新的有效出口结果才允许受保护启动。异常不会自动重新启动 Claude，也不修改账号存档。
- 节点切换本身产生一条提醒，不会把随后的新节点出口基线再报成第二次 IP 变化。重复轮询同一故障不会反复弹通知。
- 普通用户的独立通知组件每秒读取 root 事件文件。通知说明原因以及是否确实停止 Claude，不带 IP、节点名称、订阅或账号信息。

轮询不是零延迟保证：节点/VPN 通常在下一次本地检查发现，IP 变化在下一次成功出口探测发现。具体响应时间由实际验收记录说明。PF 仍保持原有状态；本次没有启用全局防火墙，不能据此宣称零数据包泄漏。

## 安装和通知

必须运行完整安装器；不能仅复制 `network-monitor.py`。root 组件位于 `/Library/Application Support/claude-switcher/`，通知应用内嵌在桌面 `Claude切换器.app` 内，并由用户 LaunchAgent 登录启动。安装器会一起编译、签名、提交或回滚这些组件。

首次运行时允许“Claude 网络防护”发送通知。macOS“系统设置 → 通知”可调整横幅和声音；专注模式可能抑制横幅。通知组件会记录权限及通知中心是否实际收到事件，未确认送达不会记成成功。系统通知权限与停止 Claude 的 root 守护相互独立。

```sh
python3 ~/.claude-switcher/network-monitor.py status
~/Desktop/Claude切换器.app/Contents/Helpers/NetworkNotifier.app/Contents/MacOS/NetworkNotifier --status
```

第一条只在 root 心跳未过期、网络证据有效且监控配置一致时成功；主界面“保镖”检查也采用该状态，不再仅凭服务注册判定通过。第二条输出本地通知权限、送达与最近事件状态。卸载会停用并删除通知 LaunchAgent；正常回滚恢复原有服务状态。

## 数据和范围

root 运行目录为 `/var/run/claude-switcher-monitor/`。私有基线文件权限为 `0600`，只保存节点/IP 哈希；面向通知和界面的状态文件为 root 所有、只读公开，不含原始地址、节点或凭据。启动时拒绝不安全的目录、符号链接和状态文件。

本次实际验收范围为 macOS + Clash Verge/Mihomo。FlClash 使用相同适配接口但尚未做本次真机验收；其他客户端保留原有巡检，Windows/Linux 未增加本次通知功能。出口检测为当前使用的 IPv4 代理路径；本机 IPv6 保持既有关闭设置。

切换目标国家时，现有 `set-region` 会在同一次管理员操作中同步后台目标国家并重启监控；客户端、代理组或地区配置不一致时，“保镖”检查会拒绝通过。
